# G80 bridge washer boundary: geometry-only stage

The geometry-only preflight identified all three exact-source, fragmented washer patches and assigned the proposed 96 outer / 32 inner circular-edge controls. It did **not** generate a mesh or call CalculiX. The results therefore establish geometry and control assignment only; node count, discrete patch area, load equilibrium, stress and installed strength remain untested.

The offline bridge adapter accepts an optional boundary callback after the source washer faces have been imprinted and verified. Its default is `None`, preserving the earlier call behavior. This stage's callback passes the exact source STEP washer-face centers and already-identified imprinted face tags to the separately published strict circle helper. It saves the face and curve inventory before applying controls, including on rejection. An independent worker trap forbids any call to `gmsh.model.mesh.generate`; the geometry-only return additionally checks that there are no mesh nodes or 3D elements. No solver invocation is present in this stage.

## One authorized boundary-controlled coarse attempt: node cap stop

One separately authorized actual-mesh attempt used the unchanged source geometry, adapter, circle helper and process-control helper from the passed geometry stage, with 96/32 washer-edge controls and 1.5 mm bulk target. The prior stage's as-run sources and record were preserved. A new case-script execution branch, its pre-launch source ledger, and the reason for its changed hash were recorded in the [coarse attempt record](../build/wo03-g80-bridge-boundary-coarse-v1/record.json). Thirty-four focused tests passed before launch. The accounting reserved **272.122851 CPU s** for prior work and at most a further 90 CPU s for this case under the existing 600 CPU s packet cap; each mesh and solver child had a 45 CPU s hard cap, sharing 120 s wall and 2 GiB RSS.

The mesh was generated but immediately failed the unchanged pre-solver node guard: **63,788 nodes** exceeded the **50,000-node** limit. The same generated mesh had **34,591 tetrahedra**, below the unchanged 75,000-tet limit. [Mesh log](../build/wo03-g80-bridge-boundary-coarse-v1/mesh.log) preserves the actual failure and [boundary inventory](../build/wo03-g80-bridge-boundary-coarse-v1/boundary-inventory.json) preserves the controlled curves. This node guard runs before mesh patch-area, material, applied-load and deck creation checks, so their outputs and the later patch/deck diagnostics were **not produced**; they are unavailable, not zero or pass. CalculiX was never invoked and no support-reaction, displacement, stress, energy or convergence result exists.

The directly supervised mesh child consumed **1.181019 CPU s** and the case took **1.237154 s wall**; the worker recorded **187,564,032 bytes** peak RSS. As-run source hashes matched before and after. No cap was increased, no alternate mesh or solver was attempted, and no strength acceptance follows. A later decision requires a separately justified bounded surface discretization or method capable of meeting the existing area and node guards together; this stopped case does not prove any such option feasible.

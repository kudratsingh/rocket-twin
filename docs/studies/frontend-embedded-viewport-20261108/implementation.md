# Embedded real-app viewport fixture — source scope

`web/viewport-check.html` is a separate Vite DEV page at the fixed loopback URL `http://127.0.0.1:5173/viewport-check.html`. The module refuses non-DEV, non-loopback, wrong-port, wrong-path and query/hash variants. The page contains no iframe until that gate passes. It then embeds the same-origin **actual Rocket Twin app** at the fixed current RP1 Design URL, including the recorded specification SHA-256 `811b3bed631fe2ce30a6b0211beecb739d40ebbbcb10e063f6beba0854631660`. No arbitrary or recursive URL can be supplied to the frame.

The three parent-page buttons request 1440×900, 1280×720 or 900×720 CSS pixels by changing **only** the existing iframe element's `style.width` and `style.height`. The iframe DOM node, browsing context, `src` and app state persist across preset changes. There is no CSS scale/transform, autoshrink, parent-window resize, browser zoom, DevTools, CDP, headless driver, app input, fetch interception or synthetic app data. The parent header is 70 px tall; the iframe has a distinct magenta outline outside its exact CSS box so a permitted native image can show the boundary. The outer page can scroll rather than shrink the embedded viewport.

The parent reads only same-origin `contentWindow.innerWidth/innerHeight/devicePixelRatio`, `documentElement.clientWidth/clientHeight` and the **iframe element's** DOM rectangle. It does not inspect the app's DOM, state or source responses. Requested and actual dimensions are displayed separately. Missing, unloaded or cross-origin values are `unavailable`; mismatch is explicit. Scrollbar-reduced document client width is reported but does not replace the `innerWidth` CSS viewport measurement. The page says that embedded dimensions alone do not establish acceptance.

This is a method fixture, distinct from a top-level Chrome viewport. Primary and the sole designated browser verifier must first confirm that the real app and backend load inside the fixed iframe, that the same iframe persists across sizes, and that the actual nested CSS dimensions match before considering any RV-Q07/Q09/Q12/Q38 responsive evidence. Native controls, keyboard paths, scroll, visible pixel findings and source identity still need their own scoped observations. No acceptance row changes from source tests or this document. If CSP or frame restrictions block the app, retain the blocked result rather than relaxing security. Existing denied methods and historical failures remain unchanged.

Focused source tests cover the whitelist, fixed same-origin URL and recursive-query rejection, CSS-only resizing without `src` mutation, and exact/mismatched/unavailable actual readouts. No browser or model execution was performed for this source packet.

# Metadata draft library: bounded integration

This separate follow-up starts after the source-template/system-map release.
It integrates FW2-024's local draft identity/history foundation and the first
metadata-only user path. It does not provide Add/Replace/Connect, a blank rocket,
candidate mass resolution, simulation admission, or a physical design revision.
Frozen RP1 and every engineering/physical gate remain unchanged.

## Scope and ownership

The Sol HIGH draft lane owns the store/router, standalone client/component,
focused tests and contract. Primary owns a small composition wrapper around the
unchanged base inspection API, the eventual Parts bank entry, shared records and
integrated acceptance. The wrapper mounts the existing API intact behind the
draft routes, preserving its catalog pins, existing docs, endpoints and CORS.
Draft preflight/actual requests retain their own exact local-origin boundary.

The UI performs only an initial list GET. Fork and label/notes saves are explicit
commands. Stale revisions preserve unsaved text and require an explicit reload;
there is no automatic retry or prepared fallback for mutable records. Every
snapshot preserves all55 source accounting occurrences and false engineering,
simulation and flight readiness. History inspection cannot overwrite the head.

## Runtime verification admission

The owner's existing port5173/8000 services and saved data must stay untouched.
One isolated local verification environment may be attempted: backend8001 and
frontend4173, in the same authorized Chrome window through the existing designated
verifier. It uses a copied, hash-verified RP1 source/inspection cache under ignored
`.cache/draft-runtime-20261109/`, with an empty separate draft-storage directory.
Only test labels/notes may be created there. No owner library, experiment, purchase,
contact, physical work or source hardware is changed.

First check loopback binding once. If denied, stop runtime startup; do not escalate,
retry through another transport, kill the owner's services or claim live success.
Startup/health has a60second bound per service; at most one focused correction.
Only agent-owned processes may be stopped afterwards. No geometry/physics solver
is run by preparation. Native execution, if admitted, has a separately declared
180second total/80second input limit and a stop on any browser guard, wrong source,
runtime ownership problem or cap. Code/SSR/API evidence stays separate from that
observation and from availability in the owner's port5173 preview.

The normal owner preview will load the integrated router on its next ordinary
`make preview` restart. Until that actual runtime route is verified, missing routes
remain an explicit unavailable state. An isolated test pass does not establish
that the existing owner's service has reloaded new backend code.

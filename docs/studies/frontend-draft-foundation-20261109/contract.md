# Source-preserving draft contract

The store, HTTP wrapper and embedded browser library implement a metadata-only
fork of frozen `G80-F2-RP1-AD1-definition-v2`. They are integrated into the normal
preview startup and **Parts bank → Saved drafts**. They preserve all 55 source
accounting occurrences, source evidence and original saved runs. No source or
physical construction is adopted by selecting a draft.

See [backend behavior and bounds](backend.md), [practical UI instructions](frontend.md)
and [runtime startup evidence](integration.md). FW2-024/FW2-A18 remain partial:
blank/composed drafts, Add/Replace/Connect, parameter edits, undo/revert, candidate
resolution and native lifecycle acceptance are not delivered by this contract.

## Persistence and request identity

`DraftStore(root)` accepts the trusted server root and exposes `fork_rp1`, `read`,
`save_metadata` and `list_drafts`. The HTTP routes require the exact source ID and
specification for forks, server UUID4 draft IDs and SHA-256 revisions. Saving
label/notes requires the loaded base revision. A stale save returns409; the UI
preserves unsaved text until explicit reload. No automatic write retry or mutable
prepared-snapshot fallback is allowed.

`source.json` preserves the unmodified parsed source specification, source-owned
parts-bank projection/revision, full RP1 inspection/evidence projection and three
frozen input path/hash references. Optional registered geometry is source-checked,
not generated by a fork. All55 definitions/occurrences retain their original group
counts, quantity1 accounting, placement, mass/budget and source conflicts. Detailed
geometry children do not create duplicate mass charges. Saved 50 g growth, 20 g aft/
motor and 55/68 g harness cases are historical source cases, not new draft results.

The source snapshot and revisions are immutable. Each revision records UUID,
source hash, frozen base ID, parent revision, sequence, UTC timestamp, operation,
label/notes and false readiness. Canonical JSON uses UTF-8, sorted keys, compact
separators, ensure_ascii=False and allow_nan=False; the revision hash excludes
its own revision_sha256 field. Only the head pointer is atomically replaced after
the immutable revision is written. POSIX locking serializes saves. A failed initial
fork can leave an explicitly incomplete directory; nothing repairs/deletes owner
data automatically. Storage/path/request limits and origin handling are specified
in the backend document, including preserved original API/CORS behavior.

## Browser admission

The client verifies exact current configuration/specification/core geometry,
55 unique records, UUID/revision forms, lineage, source references, the strict
parts-bank projection, unchanged source between saves and false readiness.
Metadata content hashes are verified using Web Crypto. Simulation eligibility,
resolved-candidate, engineering acceptance and flight readiness remain false.
The server independently verifies the complete immutable source content hash.

These are admission pins, not fallback data. A future source/storage-contract
change requires an explicit client update. Viewing history is read only; it does
not replace the current editor/head. Closing/reopening the Parts bank or changing
its sections preserves unsaved metadata for the same loaded source. A page reload
or source change discards in-memory unsaved text; only successful saves persist.

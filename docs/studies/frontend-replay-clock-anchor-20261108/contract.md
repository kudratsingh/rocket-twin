# Playback RAF clock anchor correction

P26 is retained as an **unqualified** actual full-case observation. Its first exported interval was invalid (`null`), and the observed UI cursor briefly moved from 0.001 s to about −0.0073 s. The existing Play effect seeded `last` with `performance.now()`; the first RAF timestamp could predate that seed by 8.3 ms. P26's raw evidence and 9.767 s overall budget overrun are unchanged. No subsequent source correction can retroactively qualify that attempt.

`createRafIntervalClock()` is a pure playback-time helper. The first finite RAF timestamp anchors the clock and returns `null`, so no elapsed time is borrowed from a Play event or `performance.now()`. Each later timestamp returns the unrounded difference from the prior valid RAF. Zero, backward and nonfinite timestamps return invalid deltas for the existing recorder to retain and flag; they do not advance the anchor, so a subsequent valid timestamp cannot double-advance after a regression. An invalid first timestamp returns an invalid delta and leaves the clock unanchored until the next finite RAF. Reset clears only the clock anchor for a new playback session.

`playbackStep` now returns the identity step for nonfinite/nonpositive elapsed time, invalid speed or nonfinite end. A finite negative end is valid for event-relative clocks: valid positive intervals retain the existing speed factor and natural end clamp across negative time. This does not filter invalid observations from the recorder or change its strict 60 fps threshold. The helper contains no physics, source data, rendering or browser control.

Focused synthetic checks reproduce wall start 1000 ms / first RAF 991.7 ms / next RAF 1008.4 ms, verify no backward cursor and only 16.7 ms of subsequent advancement, cover irregular speed and endpoint clamp, and preserve invalid later intervals and unknown values. They are source checks, not a native performance result.

# Experiment tracking and recorded Analysis recovery

This bounded implementation fixes two concrete workflow gaps found while checking RV-Q06, RV-Q22, RV-Q24, RV-Q32 and RV-Q33. It uses existing saved records and software-only response fixtures. No simulation, solver, browser, physical specification or dependency change was performed. Primary integration owns publication and shared acceptance ledgers.

## Owned implementation

- `web/src/experiments/Experiment.tsx`: status monitoring, accepted-member panel, saved-attempt observation/export, independent library-refresh errors and cancellation notice.
- `web/src/experiments/attemptMonitor.ts`: accepted/saved membership guards, independent member status reads, summary/export and HTTP/JSON error handling. Reads contain no submission logic.
- `web/src/analysis/AnalysisWorkspace.tsx`: response admission, source-bound payload state, read-only retries and playback-rate wording.
- `web/src/analysis/responseGuard.ts`: runtime catalog/manifest schema/source checks and exact artifact allowlist.
- `web/src/analysis/display.ts`: nonempty exact source-fingerprint admission and exact-time payload validation.
- Unique tests: `web/tests/remaining-attempt-workflow.test.mjs` and `web/tests/remaining-analysis-workflow.test.mjs`.

The pending member IDs block another submission while observation is paused. Per-member last observed statuses remain explicit, including `queued`, `running`, `cancel_requested`, `complete`, `failed`, `cancelled` and `interrupted`. `cancel_requested` is nonterminal. A failed member does not erase successful siblings or finish an active sibling. The GET monitor is cancelled on effect cleanup; late responses cannot update abandoned observation. The run library has a separate generation guard, so older refreshes cannot replace newer status lists.

Failed/incomplete metadata export includes the selected run ID, each exact saved member record, explicit null records and `missing_members` for unavailable siblings, plus `telemetry_included: false`. Request, effective settings, errors and source hashes remain exactly as recorded. Reusing a request still creates only a reviewable draft; the existing explicit Run action starts a separate attempt, with no source/CAD borrowing.

Analysis guards follow the existing backend `rocket-twin.analysis.v1` contract. Historical incompatible results remain inspectable with their existing reason when structurally valid. The two saved archived G80 nominal-fin manifests present locally passed the new response contract without regeneration. Missing optional cache files cause that source-read test to skip on other checkouts; software-only contract tests always run. The guards add no prepared-data or historical-geometry fallback.

## Validation and limits

The focused suite contains **32 passing tests**, including **11 new workflow cases**. It covers accepted membership, mixed terminal/nonterminal batch states, cancellation acknowledgement, partial GET failure and status-only resume, aborted/foreign responses, failed/missing member exports, HTTP500/malformed/transport distinctions, exact catalog/run/source matching, valid zero/null gaps, invalid timestamps, manifest-scoped artifact paths and two existing optional legacy manifests. Existing experiment SSR, request ordering, run exports, RP1 scalar-only Analysis and comparison tests remain passing. TypeScript typecheck, targeted ESLint and Prettier checks pass.

These are source, pure-function, asynchronous software-fixture and SSR checks. They do not establish the acceptance rows' native-browser interactions, zero orphan work under actual cancellation, worker termination timing, compatible spatial fields, full-rate rendering performance or engineering/physical/flight readiness. No Replay performance/helper import was added: primary will integrate the independent rendering lane after this workflow snapshot.

## Preserved contracts and migration seam

1. **One resolved source per displayed configuration.** Keep the current `G80-F2-RP1-AD1-definition-v2` spec, AD1 attachment definition, inspection geometry and all 55 stable part IDs pinned. Archived `modular-performance-v1` CAD/runs and C1/FP1/FR1 studies remain separate, with FP1/FR1 unadopted. A child feature of a part is not a new BOM or mass entry. A candidate gets its own immutable identity and source revision; the frozen current vehicle is never mutated by browsing or composing it.
2. **Single source of engineering values.** The source-owned parts bank may expose YAML/CadQuery-derived dimensions, material, provenance, maturity, availability and `learn:` content. A visual child, stock reservation, mesh, download or blank editor field cannot supply missing mass, inertia, fit, installed joint strength or qualification. Complete candidate resolution, geometry, mass properties and simulation eligibility belong in the existing Python source/validation path. The frontend renders the result and requests existing Python/JAX experiments; it computes no flight physics.
3. **Preserve working journeys.** Design inspection, 2D/3D selection, part evidence and diagram links, scoped CAD/STEP exports, Engineering, Experiments, saved runs, replay/comparison, Analysis missingness and historical configuration links remain reachable. Keep legacy URLs or provide an explicit source-preserving redirect; unknown/stale links get a recoverable notice, never a silently selected different part. Panel, selection, camera, scroll and download changes require a focused migration regression.
4. **No framework swap or dependency upgrade.** Use the pinned React/Three/FastAPI/JAX/CadQuery stack and existing source/export contracts. A fresh build regenerates derived geometry from pinned inputs or proves exact packaged bytes; generated meshes do not become independent design sources. The original sole browser verifier, `/root/browser_access_sol`, owns permitted current Chrome observations. No headless/CDP, other window or denied-method retry.

### Negative cases required before candidate or run admission

- **Source and identity:** duplicate/unknown part ID, removed parent, stale spec/CAD/inspection hash, foreign archive mesh, unsupported units or frame, missing GLB/STEP, file with a catalog name but wrong SHA, wrong external-board revision/license, or an absent source path. In every case, retain the known source status and an explicit unavailable reason; do not substitute another asset.
- **Assembly and accounting:** incompatible bore/tube/motor or interface, physically conflicting envelopes where the source can establish the conflict, absent attachment/thermal/recovery data, incomplete quantities, duplicated tab or gusset mass, missing finite inertia or center of mass, unknown material property, and a mass/propellant limit violation. Reject an ineligible simulation request before work begins. Where a source cannot determine fit or strength, mark it unresolved rather than inventing a pass.
- **Candidate lifecycle:** interrupted save, delayed A/B responses, a stale active-selection URL, an imported candidate referring to unavailable revision, simultaneous tab drafts, and back/forward between current, archive and candidate. No route, cached child or export may attach a prior candidate's part to a different source tuple. A failed candidate remains inspectable as a rejected draft with reasons, not an active design.
- **Experiment and evidence:** unsupported RP1 or unadopted FP1/FR1 request, invalid override, worker error, acknowledged versus completed cancellation, failed batch member after reload, incompatible run pair, missing event/channel, missing or scalar-only Analysis, and a stale analysis registration. Preserve actual failures and gaps. Do not synthesize telemetry, stress maps, CFD, recovery dynamics or a native performance pass.

## Migration test order and evidence classes

1. **Source contract:** pin current and archive configuration/spec/CAD/geometry identities; inventory every bank entry and generated asset. Snapshot only the contract and source hash, not a duplicated bulk geometry fixture. Compare source positions and units to exported inspection files; prove all required 55 IDs are still present and missing geometry remains missing. An asset regeneration mismatch stops migration before UI testing.
2. **Backend eligibility:** run schema/resolver and CAD-export checks for one known current fixture and each newly supported candidate class. A proposed candidate without full mass/inertia or other required inputs fails closed. Use `tiny` CPU smoke for an *eligible* experiment only; preserve immutable run IDs and exact record bytes. Engineering solver acceptance is a separate gate.
3. **Frontend behavior:** focused tests cover route hydration/writeback, changing active source while a detail is open, source-based 2D/3D selection, displayed versus source bounds, parent/child identity, layer and camera reset, dialog focus, scoped downloads, unavailable/error states and valid draft reuse. Test against actual tracked source metadata and freshly generated assets, not fabricated geometry or a checked-in copy of derived mesh files.
4. **Integrated native:** the designated verifier performs bounded actions at one exact head/source tuple in the permitted Chrome window. Record viewport, action sequence, selected IDs, URLs, source labels, visual result and final restored state. Recheck changed interactions; earlier P packets and SSR/static renders cannot pass new controls. A changed/private context or unsupported browser operation stops that packet.
5. **Engineering/physical:** Python/RocketPy comparisons, WO-03 structural/thermal/tolerance/recovery/flutter evidence, installed fit, actual hardware measurements, build, WO-10 review and flight release retain their own criteria and authorizations. A detailed displayed assembly, candidate validation or JAX run does not clear them.

## Stop and release rules

- Stop a slice on a changed source tuple, unexplained byte/triangle/bounds mismatch, missing required input, stale cross-candidate attachment, an out-of-scope solver/physics need, or an unsupported browser operation. Preserve the failed artifact and identify the smallest source or interaction correction; do not widen the slice or substitute estimates to reach a pass.
- Declare a case count and CPU/wall cap before each future source export, candidate smoke or native packet. The pinned environment expects `tiny` CPU smoke to finish in under two minutes; an overrun is a stopped diagnostic, not permission for a larger run. Keep one source fixture and one focused correction per packet unless the primary records a new scope. The failed Q30 performance campaign needs its own fixture, visible-scene method, host and cap before any retake.
- Keep experimental work bounded to declared CPU `tiny` fixtures and existing authorized local simulator paths. A paid run, supplier contact, purchase, fabrication, loading, physical test, flight or new hosted deployment needs its separate existing authorization. All five inquiry drafts remain **UNSENT**.
- Publish a v2 increment only with its actual source/head, generated-asset proof, relevant local checks and required hosted checks. Report *implemented*, *native observed*, *engineering validated* and *physical accepted* separately. Outstanding exact viewport matrix, real Analysis fields, Q30 failure, frozen RP1/D1 and WO-03/04/05 gates remain visible until their own evidence changes.

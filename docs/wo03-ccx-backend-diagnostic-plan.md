**Resource correction:** the shared supervisor measures and limits root-process RSS only. Historical plans below called this a tree limit; that claim was not established. Reported peak samples are root-only, and aggregate tree memory remains unverified. Original execution records are preserved.

**B1 is closed and stopped:** native SPOOLES completed, and the selected 593-node, two-step displacement and reaction vectors were decoded and checked against same-run DAT and the known B displacement solution. This verifies that narrow installed-binary I/O case, not all FRD formats or the bridge model. Step 1’s force residual of 5.722046e-6 N plus float32 encoding bound of 8.583069e-6 N exceeds the unchanged 1e-5 N criterion; the interval permits equilibrium, so its force certificate is unavailable. Step 2 passes individually, but there is no aggregate B1 pass. No B2 or actual bridge case was run.

This is a numerical/output diagnostic, not an engineering acceptance.

## Historical preparation and proposed controls

The following describes the pre-B1 proposal and its planned controls; statements about proposed cases or future execution are historical and do not authorize additional runs.

The candidate sequence is B1 using default SPOOLES and binary U/RF, B2 using `SOLVER=ITERATIVE CHOLESKY` and binary U/RF, then the saved actual coarse input with the latter solver only if both fixture gates pass. The original B and bridge meshes, geometry, materials, constraints, loads, steps, amplitudes and tolerances are preserved. Each step adds `*NODE OUTPUT` with `U,RF`; iterative decks change only the two `*STATIC` cards. The generator checks exact byte-for-byte reversal of its allowed substitutions. [Preflight](../build/wo03-ccx-backend-diagnostic-v1/preflight.json) records original and prepared deck hashes and before/after SHA-256 for both saved input/meta/DAT sets. Installed `/opt/homebrew/bin/ccx` matched `2349c77ebd8302615828ac3911caac45fb0a39363914ee555db1c7e3a86250bf`. Original A/B/D fixture packets and prior actual-case failure stay closed and immutable.

The [CalculiX 2.23 manual](https://www.dhondt.de/ccx_2.23.pdf), §§7.98–7.99 and 7.123, documents binary/ASCII `*NODE OUTPUT`, RF semantics and the iterative selector. Current upstream [`frd.c`](https://github.com/Dhondtguido/CalculiX/blob/master/src/frd.c) identifies DISP and FORC vector component headers; [`frdvector.c`](https://github.com/Dhondtguido/CalculiX/blob/master/src/frdvector.c) writes a native int and three float values in its binary path. That development source is **not pinned to the installed 2.23 source archive**. The earlier installed-binary thermal probe verified scalar NT/RFL, not this vector framing; coordinates do not prove vector width. The provisional decoder expects exact headers, four components, little-endian 32-bit node IDs and three float32 values, ordered complete unique node IDs, finite data and known subsequent framing. Synthetic tests exercise valid, wrong-ID, truncated and nonfinite records. They do not validate an actual vector FRD or the assumptions about step metadata.

Before execution, complete a fail-closed native supervisor and the following readout contract. Verify solver and all sources/inputs before and after, capture logs and runtime resources, decode exactly two steps and independently verify step identifiers/times rather than relying on field order alone. Validate all B node IDs against the deck, node count and every component of the binary U/RF against same-run separately labeled DAT U/ALL-RF/SUPPORT-RF within the printed decimal interval **plus binary encoding interval**. Use metadata's bar membership, axial coordinates and piecewise `u_z=(F/A)[min(z,10)/100 + max(z-10,0)/10000]` for the loaded bar, with `u_x=u_y=0` and each step's 50/50/50 or 150/0/0 loads; all-node errors and free ends must satisfy the existing 1% fixture criterion. This checks the actual vector format and field identity, not merely header appearance. Any missing/extra/ambiguous field, duplicate ID, nonfinite value, unsupported endianness or framing, unexpected step, inconsistent DAT interval or analytic failure stops the packet.

Reconstruct support force and moment using actual support IDs and compare against known load resultants and moments, accounting for external-load semantics. For each float32 value bound the encoded underlying value by its adjacent representable rounding interval, including zeros and subnormals, and propagate those intervals conservatively through sums and moments. The unchanged strict force criterion is **observed absolute residual plus its encoding uncertainty ≤ 1e-5 N**; if an interval merely permits equilibrium, mark precision unavailable, not pass. Existing fixture displacement threshold stays 1%. Check two load steps and no unaccounted supports or loads. Earlier DAT-derived float32 bounds predict roughly 8.94e-6 N per B step, leaving little room for residual; this is a prior estimate, not a result for the proposed path. The actual bridge's larger observed 104.7 N residual and 32.23 N·mm reciprocal-work discrepancy remain unexplained; float32 encoding alone was estimated to exceed the strict force threshold there. A successful B cannot by itself qualify or repair the actual model.

The proposed packet cap is 120 CPU / 120 wall s per case, 60 CPU s setup reservation and 120 CPU s parent reservation, totaling 540 CPU s against 600. A 2 GiB live tree RSS guard, one requested worker and `CCX_NPROC_EQUATION_SOLVER=1`, `CCX_NPROC_RESULTS=1`, `CCX_NPROC_STIFFNESS=1`, `OMP_NUM_THREADS=1` must be enforced and checked in available logs; no OS affinity is claimed. Stop on first tool, parser, convergence, numerical, precision-gate or resource failure; do not retry, change solver settings or advance to the actual deck. Resource usage of this brief input-only preparation was not sampled and is unavailable, not zero. Two synthetic tests passed; Ruff/Black passed. No geometry generation, installed dependency change, native solve or strength acceptance occurred.

## Historical B1 prelaunch continuation

The earlier implementation gap above is superseded: the B1-only supervisor and checks are now implemented, with native execution **disabled** in the study configuration. The default phase remains preparation only; explicit `--phase b1` also refuses to start while that flag is false. There is no B2 or actual-case launch path or automatic continuation in this code. A later explicit primary decision may admit B1 by changing that flag alone; all other configuration fields must match the preserved input-only config and all pinned sources and B1 deck must still match the reviewed ledger.

The candidate parser checks upstream fixed-column `1PSTEP` counter/increment/step and `100CL` time/node count/binary-mode flag, exact vector component labels, complete 593-node IDs, field sequence, 16-byte records, finite values, boundary markers and no extra result fields. The B gate independently checks the exact ALL/SUPPORT sets, unique full support constraint, no MPC/transform/equation/DLOAD, deck CLOAD versus saved metadata, all binary U/RF components against separately labeled same-run DAT decimal intervals plus binary intervals, and all-node layered-bar analytic displacements. It reports force and moment residuals with conservative float32 rounding bounds; strict force passes only when residual norm plus bound is at most 1e-5 N. Incomplete, different or unknown installed framing stops; matching the development source and synthetic tests does not certify the installed binary in advance. Exact sources and generated deck hashes are frozen in [reviewed v2 preflight](../build/wo03-ccx-backend-diagnostic-v2/preflight-reviewed.json); the initial v2 preflight and original v1 snapshots remain preserved. V2 candidate deck hashes equal v1.

The supervisor requests one thread, verifies the SPOOLES log reports one CPU, applies a 120 s hard parent CPU cap and 120 s hard child CPU cap, 120 s child wall and live 2 GiB root-process RSS limits (the intended tree-wide limit was not established), and records status, logs and source hashes in a fresh B1 folder. The 60 s setup and 120 s parent reservations plus three proposed 120 s cases remain 540 s under the 600 s packet cap; cumulative usage is not claimed until measured. V2 initial input-only preparation measured 0.23 s wall, 0.15 s user and 0.06 s system; the prior preparation and subsequent small test/setup usage were not measured and are not treated as zero. Five focused tests pass, including a saved-B DAT to **synthetic** binary check, bad step, endianness, node ID, truncated/nonfinite records and extra-field rejection. Ruff and Black pass. No solver or new mesh was run.

The actual coarse mesh has 42,850 declared nodes but 42,715 tetrahedron-used nodes; 135 unused nodes are not loaded or supported. A future actual-case decoder must establish the installed writer's emitted-node policy and explicitly reconcile all loaded and supported IDs. B's 593-node proof must not be extrapolated to that different node set. Actual-case admission and any B2 run remain separate primary decisions.

## Separately admitted B1 pilot

The primary admitted exactly one B1 SPOOLES case; the disabled configuration was restored after the run's source-after hashes were recorded. [Admission](../build/wo03-ccx-backend-diagnostic-v2/primary-admission.json), [raw assessment](../build/wo03-ccx-backend-diagnostic-v2/native-B1/assessment.json) and [restoration](../build/wo03-ccx-backend-diagnostic-v2/restoration.json) preserve the original disabled and as-run admitted configuration hashes. No B2 or actual bridge case ran.

CCX exited 0 and its log identified the symmetric SPOOLES solver using one CPU. The proposed little-endian float32 vector reader recognized both steps' DISP/FORC headers, step/time metadata and complete 593-node IDs, and all binary vectors matched the corresponding same-run DAT print intervals; all-node B analytic displacement checks passed. Maximum absolute axial displacement errors were 1.1921e-8 and 2.3842e-8 mm. This is direct evidence for the selected output fields and B fixture on this binary, not a general guarantee for all FRD layouts or actual-mesh node emission.

The **aggregate strict force certificate is unavailable**, so the packet stopped. Step 1 has observed force-residual norm 5.722046e-6 N and conservative float32 encoding bound 8.583069e-6 N: their sum exceeds the unchanged 1e-5 N criterion, while the interval permits equilibrium. Step 2 individually passes with residual approximately 1.42e-13 N and bound 5.722046e-6 N. Force precision unavailable is not a pass, a reason to relax the threshold, or proof of a physical imbalance. B1 does not qualify the actual bridge or resolve its earlier large discrepancy.

The owned child used 0.081275 s measured CPU, 0.164128 s supervised wall and 171,261,952 bytes maximum sampled root-process RSS; parent supervisor deltas were 0.002473 CPU s. Prior setup was only partly measured and remains unavailable rather than zero. Hard child and parent caps were 120 CPU s each, child wall 120 s and live root-process RSS 2 GiB; one CPU was requested and observed in the SPOOLES log, without an OS-affinity claim. Raw binary FRD and DAT hashes are retained in the restoration record. No installation, remeshing, model change or extra native case occurred.
